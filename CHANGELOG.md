# Changelog

## Unreleased

- **gibbon** (0.1.2): fixed `scripts/backup.sh` failing on every run with exit 2 (`mysqldump: [ERROR] unknown option '--skip-ssl'`). The scripts hardcoded MariaDB's `--skip-ssl`, but on the Magneto Agent's Ubuntu 24.04 base `default-mysql-client` is Oracle MySQL 8.0, which only takes `--ssl-mode`. `verify-health.sh` and `php-info.sh` had the same flag, and since they send mysql stderr to `/dev/null`, every DB check failed silently. The new `scripts/lib/mysql-tls.sh` reads the installed client's `--help`. For MySQL it passes `--ssl-mode=DISABLED --get-server-public-key`: without the key flag, a non-TLS `caching_sha2_password` login fails with ERROR 2061 when the server's auth cache is cold, e.g. after a gibbon-mysql restart. For MariaDB it keeps `--skip-ssl`, which 11.4+ still needs because it rejects the server's self-signed cert. `scripts/tests/mysql-tls.test.sh` is a hermetic test that runs all three scripts against fake clients of both flavours.
- **ai-studio** (0.2.1), **gibbon** (0.1.1), **moodle** (0.1.2), **odoo** (0.1.1), **wordpress** (0.1.2): the AI Assistant's model key is now Clouve-managed, one key per deployment, delivered to the Magneto Agent as `MAGNETO_AGENT_LLM_KEY` and exported to Claude Code as `ANTHROPIC_AUTH_TOKEN`. The tenant key file `~/.claude_api_key`, the key prompt and the Preferences panel are gone. Each `SKILL.md` key-protection rule now names the managed key; gibbon's `rotate-admin-credentials` playbook section 3 says Clouve rotates it and lists where it lives; gibbon/odoo `learnings.md`, gibbon `reference/shell-access.md` and moodle `reference/observability.md` match. The ai-studio description drops the retired "agent client selection".
- Dropped Codex CLI and Gemini CLI from `README.md` and the `marketplace.json` description: the AI Assistant runs Claude Code only.
- **wordpress** (0.1.1): channel-reality update — the Clouve-packaged WordPress app is now agent-enabled (magneto `develop` commit `7f4e6ca`: `x-clouve-agent` block + `clouve-ops` sshd in BOTH sibling images + per-app persona + `mariadb:12.3` pin). The same change ships `clv-docker-compose-basic.yml`, so packaged WordPress publishes TWO listings from one image pair: "WordPress" (basic, agent-off — sshd never starts because `CLOUVE_OPS_PASSWORD` is not injected, i.e. shell-less like before) and "WordPress with AI Assistant" (agent-enabled). On the agent-enabled listing the `clouve-ops` SSH probe is now EXPECTED GREEN and wp-cli is reachable (`sudo -u www-data wp --path=/var/www/html …`); verified live on a Kubernetes deployment (SSH + sudo both siblings, wp-cli 6.9, `verify-health.sh` GREEN). `learnings.md` entry updated; vanilla developer composes remain shell-less and probe-first semantics are unchanged.
- **wordpress** (0.1.0): new DevOps plugin — safely operate a WordPress site deployed on Clouve (backups/restores, plugin and theme management, core updates, site URL changes, wp-cron, hardening, diagnosing WSODs/500s/lost admin access). Unlike moodle/gibbon, the WordPress sibling images ship no `clouve-ops` sshd and the vanilla `wordpress:<ver>-apache` image has no wp-cli, so the skill is **channel-honest**: every playbook step is labeled TCP-mysql / HTTP / shell-conditional, probes for the SSH channel before planning, and documents SQL/HTTP fallbacks where they exist (and says plainly when an operation genuinely needs a file channel). Grounded in the Clouve-packaged image's installer entrypoint behavior (boot-time `siteurl`/`home` reconciliation from `WORDPRESS_SITE_URL`, forced `WP_DEBUG_DISPLAY` off, uploads re-chown, hardcoded `wp_` install detection) with a do-not-fight list. Ships `install.sh` (default-mysql-client + openssh-client + sshpass, moodle-pattern).
- Added the missing `odoo` row to the README Plugins table (the odoo merge skipped it).

- **ai-studio** (0.2.0): the workspace is no longer blank — it ships pre-seeded with a MERN starter project already running in development mode, and `supervisord` (not systemd) is PID 1. The "use systemd for anything long-lived" operating principle is now "use supervisord" (`/opt/clouve/supervisord.d/` program confs + `supervisorctl`); verification examples switched from `systemctl is-active` to `supervisorctl status`; description updated to match. The clv-proxy "Publishing an HTTP service" and "Publishing raw TCP via SSH tunnel" sections were already correct for the seeded model and are unchanged.
- **mern** (0.2.0): added a "Process supervision: systemd or supervisord" section — every `systemctl`/`journalctl` step now carries a supervisord variant for hosts where systemd is not PID 1 (notably the AI Studio workspace, whose seeded starter is the living example). Noted the AI Studio exceptions to the `127.0.0.1` bind rule (clv-proxy requires `0.0.0.0`) and to the "never supervise a dev server" rule (on AI Studio the supervised Vite dev server is the point), and that MongoDB comes pre-installed/supervised there.
- **gibbon**, **moodle**: added per-plugin `install.sh` runtime install hooks at `plugins/<name>/install.sh`. [Magneto Agent](https://github.com/Clouve/magneto-agent)'s marketplace plugin-stager runs each one after staging the plugin payload to apt-install the binaries the skill's scripts shell out to (`default-mysql-client`, `openssh-client`, `sshpass`). Replaces the previous per-app `apps/<name>/image/ai-studio/` Dockerfile layers in [Clouve/magneto](https://github.com/Clouve/magneto), so both apps now consume the upstream Magneto Agent image directly with no per-app image layer.
- Documented the per-plugin install hook convention in `CLAUDE.md`.
- Updated `README.md` and `CLAUDE.md` for the upstream platform changes: the AI Studio image source moved out of `Clouve/magneto` (`apps/ai-studio/image/`) into the standalone [`Clouve/magneto-agent`](https://github.com/Clouve/magneto-agent) repo and was renamed **Magneto Agent**. The activation env var was renamed `AI_STUDIO_SKILLS` → `MAGNETO_AGENT_SKILLS` and now takes Claude Code marketplace URLs (with optional `?plugins=` filter and `#branch` ref) rather than `<Category>/<Name>` plugin slugs against this repo's tree.

- Removed all `CONTEXT.md.tpl` files (root and per-skill); AI Studio persona templates are now managed in a separate repo.
- Dropped `Web_Development/MERN` and `Web_Development/Next.js`: they only contained `CONTEXT.md.tpl` (no `SKILL.md`), so nothing remained after the persona templates moved out. Add them back as plugins when they have a `SKILL.md`.
