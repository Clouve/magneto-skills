# Playbook: Harden a Fresh Install

Run through this after a tenant's first successful launch. Most items are settings-level changes in Gibbon's UI; a few need `config.php` tweaks or Clouve platform actions.

## Preconditions

- [ ] Gibbon is installed and admin login works.
- [ ] The tenant has acknowledged they want their instance to be production-suitable (this playbook is not useful for a demo/scratch instance).

## Checklist

### 1. TLS / HTTPS only

- [ ] `$GIBBON_URL` is `https://…` (check the app's env; `applicationUrl` should produce HTTPS).
- [ ] The cert on `$GIBBON_URL` is a real CA-signed cert, not self-signed. From AI Studio:
  ```bash
  curl -svI "$GIBBON_URL" 2>&1 | grep -E "issuer|subject"
  ```
  If the issuer looks like a self-signed chain, escalate to Clouve ops — see [CLAUDE.md](../../../CLAUDE.md) "Self-signed TLS certificates break WebSocket" section.
- [ ] `gibbonSetting(absoluteURL)` matches `$GIBBON_URL` (auto-synced on every restart by `update-config.sh`):
  ```sql
  SELECT value FROM gibbonSetting WHERE scope='System' AND name='absoluteURL';
  ```

### 2. Admin credentials

- [ ] Initial `GIBBON_PASSWORD` was generated by Clouve's `applicationPassword` type (not a default like `admin`). Verify: the tenant should have received the generated password once in the marketplace UI at first launch.
- [ ] Admin has changed the password from the initial one. Ask the tenant to confirm. Cannot verify from the DB side (hashes aren't reversible).
- [ ] Admin has **enabled 2FA** on their account. Verify:
  ```sql
  -- 2FA status lives on gibbonPerson; column name varies by version, likely gibbonPersonTwoFactor* or similar.
  -- Safer: ask the tenant to confirm in their profile.
  ```

### 3. Password policy

Gibbon has a built-in policy. Tenant sets via **System Admin → Security Settings** (or the equivalent). Recommended minimums:
- Minimum length: 12.
- At least one uppercase, one digit, one special character.
- Reuse prevention: last 5 passwords.

Check what's currently set:
```sql
SELECT name, value FROM gibbonSetting WHERE scope='User Admin' AND name LIKE 'passwordPolicy%';
```

### 4. Impersonation (v30+)

v30.0.00 added `Impersonate User`. It is OFF by default — requires an explicit flag in `config.php`. Leave it off unless the tenant has a specific reason (e.g. support staff who need to reproduce user-reported issues).

If they want it on, walk through the risk (see [reference/security.md](../reference/security.md#impersonate-user)) and then they add `$enableImpersonation = true;` to `config.php`. Through the UI: there's no toggle — it's purely a file-level opt-in.

### 5. Public registration

Open registration lets anyone on the internet submit an application to attend the school. Usually the tenant DOES want this, but they should know the settings:
- **System Admin → Public Registration Settings**: is it on? Which year groups accept applications? Is a processing fee required?
- **Admissions → Manage Applications**: staff review queue.

If the tenant doesn't want open registration at all, disable it at the settings level. Don't leave it at "accepting applications but ignoring them" — applicants get confusing responses.

### 6. Telemetry / cutting-edge code

Auto-install sets both to safe defaults — verify:

```sql
SELECT name, value FROM gibbonSetting
WHERE scope='System' AND name IN ('statsCollection', 'cuttingEdgeCode');
-- Expect: statsCollection='N', cuttingEdgeCode='No'
```

If either is set to the opt-in value and the tenant didn't request it, flip it off.

### 7. SMTP / email

Without a working mailer, password resets don't send, behaviour letters don't deliver, parent summaries don't arrive. The tenant must configure SMTP at **System Admin → Email Settings**:
- Host, port, TLS, username, password.
- "From" address should match a domain they control.
- Send a test email to themselves and verify receipt.

Check from the DB:
```sql
SELECT name, value FROM gibbonSetting
WHERE scope='System' AND name LIKE '%mail%' OR name LIKE '%smtp%';
```

### 8. Cron

See [reference/operations-and-signals.md#the-in-container-cron-daemon](../reference/operations-and-signals.md). Verify with the tenant that scheduled tasks are firing — check `/var/log/gibbon-cron.log` (requires ops, or proxy via `gibbonLog` as described).

### 9. File upload limits

Default 20 MB per file (set in the image's `php.ini`). Most schools are fine with this. If the tenant needs higher (e.g. video uploads for art class), it requires a rebuild of the image — not in scope for the tenant. Document as a known ceiling.

### 10. Backup cadence

Not a security setting per se, but load-bearing. Tell the tenant:
- Run a backup before every upgrade, module install, or rollover (this skill will do it for them if they ask).
- Periodically (monthly at minimum) download the backup file from `$HOME/backups/` in AI Studio to an off-site location.
- Clouve's `ai-studio-home` volume survives container restarts but is not an off-site backup.

### 11. Audit user accounts

Any accounts that shouldn't exist:

```sql
-- All users, grouped by role
SELECT r.name AS role, COUNT(*) AS count
FROM gibbonPerson p
JOIN gibbonRole r ON p.gibbonRoleIDPrimary = r.gibbonRoleID
GROUP BY r.name
ORDER BY count DESC;

-- Any users with the Admin role
SELECT p.username, p.email, p.dateStart, p.status
FROM gibbonPerson p
JOIN gibbonRole r ON p.gibbonRoleIDPrimary = r.gibbonRoleID
WHERE r.name = 'Administrator';
```

Tenant confirms the Admin list is intentional. Any non-tenant admins should be demoted or investigated.

### 12. Log review

Glance at `gibbonLog`:

```sql
SELECT timestamp, title, gibbonPersonID
FROM gibbonLog
WHERE timestamp > NOW() - INTERVAL 7 DAY
  AND title IN ('Login - Success', 'Login - Failed', 'Password Reset', 'Permissions Updated')
ORDER BY timestamp DESC
LIMIT 50;
```

Look for unusual login patterns (multiple failures, logins at odd hours from unexpected users). Discuss with the tenant.

## Final confirmation

Summarize what you verified and what you changed. If any item is still "to do" (e.g. "tenant needs to configure SMTP themselves"), hand it back explicitly — don't leave it implicit. The hardening is only as good as the items the tenant actually owns.

## Do NOT

- Do NOT disable 2FA for the tenant "just for now."
- Do NOT set `statsCollection='Y'` or `cuttingEdgeCode='Yes'` without an explicit opt-in.
- Do NOT expose the installer directory — it is self-gated by `config.php`, do not remove it or move it.
- Do NOT skip the SMTP config check. A hardened Gibbon with no mailer looks secure but can't do half its job.
