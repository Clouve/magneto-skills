# Playbook: Rotate Admin Credentials

Three distinct things that can be "rotated" here, with very different procedures:

1. **Gibbon admin user password** — the `GIBBON_PASSWORD` the tenant uses to log into Gibbon's UI as the first admin.
2. **Gibbon DB credentials** — the `DB_PASSWORD` Gibbon uses to connect to `gibbon-mysql`. If your organization's admins see Database password on the deployment's Settings tab, one of them can press Rotate database password there (Rotate database passwords, in a kit). Otherwise Clouve support can do it for you (section 2).
3. **The AI Assistant's access key**: Clouve manages it, one key per deployment. You don't rotate it from here (see section 3).

Pick the right one before doing anything.

## 1. Rotate the Gibbon admin user password

**Do this in the Gibbon UI. Do not touch the DB.**

The tenant:
1. Logs into Gibbon as an admin (if they remember the old password) OR uses the **Forgot Password** flow from the login page (sends a reset email to the admin address).
2. Navigates to their user profile → **Change Password**.
3. Sets the new one.

If they're locked out (forgot password, no mailer configured):
- **Preferred:** have them configure the mailer first (System Admin → Email), then use Forgot Password. This is also a good outcome in its own right — notifications will start working again.
- **Fallback with tenant ack:** an admin user's password hash lives in `gibbonPerson.password`. Gibbon uses its own hasher (check `Gibbon\Services\PasswordEncoder`). You can reset it by having the tenant run the password-reset script upstream Gibbon ships, but **we do not have a CLI for this in the app**. Do not fabricate a reset SQL statement — a MySQL `UPDATE gibbonPerson SET password='...'` with a hash you generated by hand will almost certainly not match Gibbon's expected format, and recovery becomes harder.

**Refuse to help if:** the user asking for the password reset can't prove they're the tenant admin (e.g. they're saying "my colleague is locked out, can you change his password for me?"). That's out-of-band identity verification, not Claude's call.

## 2. The Gibbon DB password: the Rotate action, or Clouve support

You can't rotate it from here. The password is the deployment's `DB_PASSWORD`, a secret Clouve generates. The image writes it into `config.php` at every start ([update-config.sh](https://github.com/Clouve/magneto/blob/develop/apps/gibbon/image/installer/update-config.sh)), so a password changed in MySQL alone stops Gibbon at the next start, and one changed in `config.php` alone is put back.

When the customer wants a new one (it may have leaked, or their policy asks for it): if your organization's admins see Database password on the deployment's Settings tab, one of them can press Rotate database password there (Rotate database passwords, in a kit). Otherwise Clouve support can do it for you. It sets a new password in the database and in the deployment's settings, and restarts Gibbon and the AI Assistant (this session ends), so Gibbon is down for a minute or two. Nobody sees the new password, and you read it again with `clv-secret GIBBON_DB_PASSWORD` after the restart.

### Do NOT

- Do NOT `ALTER USER` the `gibbon` database user, even with root's password in hand.
- Do NOT hand-edit `$databasePassword` in `config.php`: the next start writes the deployment's value back.

## 3. The AI Assistant's access key

Clouve manages this key. The platform issues one per deployment, caps it at the deployment's monthly AI usage allowance plus any usage the tenant bought this month, and blocks or deletes it when the AI Assistant is switched off or the deployment is paused or removed. Neither you nor the tenant rotates it from inside the container.

Where it is in the Magneto Agent container:

1. The container environment, as `MAGNETO_AGENT_LLM_KEY` (set from a Kubernetes Secret the platform manages).
2. Your session, as `ANTHROPIC_AUTH_TOKEN`.
3. `/etc/profile.d/clouve-env.sh`, which login shells source.

### Procedure

If the tenant thinks the key has leaked, send them to Clouve support. Clouve replaces the key, and the usage already counted this month carries over to the new one. Nothing changes in Gibbon.

### Do NOT

- Print the key to chat, even redacted.
- Copy it to a file, a command line, or another container.
- Send it to any endpoint other than the model gateway in `ANTHROPIC_BASE_URL`.
- Edit the environment or `/etc/profile.d/clouve-env.sh` to swap in a different key.
